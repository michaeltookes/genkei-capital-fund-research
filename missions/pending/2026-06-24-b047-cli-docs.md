# Document every `genkei` CLI subcommand under `docs/cli/` (B-047)

## Context
**Backlog ref:** B-047 (Phase 3 — Custom CLI).

The CLI is the agent's only interface to the lake. When the agent doesn't know how to query something, it should read a doc — not reverse-engineer the source. Today there is no `docs/cli/` directory at all. This mission writes one reference page per subcommand.

The live subcommands are in `src/genkei/cli/` (each registered in `cli/__init__.py`). As of this writing they are: `backtest`, `cot`, `crowding`, `eight_k_impact`, `etf_flows`, `filings`, `holdings`, `insider_clusters`, `insiders`, `macro`, `macro_regime`, `news`, `news_sentiment`, `prices`, `query`, `relative_strength`, `revenue_divergence`, `signals`, `stablecoin_flow`, `tvl`, `tvl_drawdown`, `watchlist`, `whales`. Derive the authoritative list at run time from `cli/__init__.py` registrations (don't trust this list if the code has moved on) — `watchlist` is a sub-Typer with `list` / `health` / `gaps`.

This is **doc generation grounded in real output** — for each command, actually run it (the lake is reachable from Michael's LAN via the gitignored `.env`: `set -a; . ./.env; set +a`) so the worked examples are real, not invented. If a command can't reach the lake in the run environment, capture its `--help` and note the example as illustrative rather than fabricating numbers.

## Acceptance criteria
- [ ] One markdown file per subcommand under `docs/cli/` (e.g. `docs/cli/prices.md`), named after the command.
- [ ] Each file contains: the command's purpose (1–2 sentences), its `--help` flag table, and at least one **worked example** showing both the default human output and the `--json` output.
- [ ] A `docs/cli/README.md` index links every page and states the one-doc-per-subcommand convention so new subcommands get a page by default.
- [ ] Examples use real command output where the lake is reachable; any illustrative-only example is explicitly labelled as such.
- [ ] `python3 -m unittest discover -s tests` still passes (doc-only; expected green unchanged).

## Notes
- Sized for one autonomous session because it's repetitive/mechanical — but it IS ~23 pages. If the session runs long, it's fine to land pages in batches across multiple commits; just don't move the file to `done/` until every subcommand has a page.
- Keep each page to roughly one screen. These are lookups, not tutorials.
- Cross-link related commands (e.g. `tvl` ↔ `tvl_drawdown`, `insiders` ↔ `insider_clusters`, `macro` ↔ `macro_regime`).
- If a subcommand's `--help` text is thin or wrong, fix the `--help` string in the source in the same mission — the doc and the `--help` should agree.
