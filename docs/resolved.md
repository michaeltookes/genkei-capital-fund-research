### R-023 — DeFiLlama backfill mode + Phase 1 hygiene migrations (B-019)
- **Resolved:** 2026-05-10 (branch phase1-cleanup, commits `f6bb302` + `80cb37e`)
- **Outcome:** Closes the last high-priority Phase 1 item with full Option C scope (every backfillable DeFiLlama endpoint), plus the two D-010 hygiene additions baked in from the start. **Three new migrations:** (1) `defillama.protocol_tvl` — sibling to `defillama.protocols`, PK `(slug, chain, ts)`, FK to `protocols(slug)`, 30-day hypertable chunks; (2) compression policies on all four `defillama.*` hypertables (segmentby = most-filtered column per table, orderby `ts DESC`, compress chunks > 30 days old); (3) 90-day retention on `meta.raw_blobs` via a TimescaleDB `add_job` running a `meta.delete_old_raw_blobs` procedure daily inside Postgres. **Backfill collector** (`python -m genkei.ingest.defillama --backfill --since YYYY-MM-DD [--endpoint X]`) walks daily timestamps for prices, iterates known slugs for `/protocol/{slug}`, and known asset_ids for `/stablecoin/{id}`. Each fetch lands a `meta.raw_blobs` row with a backfill-shaped `endpoint_name` (`prices_historical_<date>`, `protocol_<slug>`, `stablecoin_<id>`). chain_tvl is intentionally not backfillable here — G-012, daily collector already pulls full chain history every run. **Resumability** per D-011: every prospective fetch checks `meta.raw_blobs.url` within a 14-day window; already-fetched URLs skip the HTTP call and copy the cached payload into the current run so the selected `source_run_id` still normalizes completely. Crashed-then-resumed runs do zero redundant work. **Backfill normalizer** (`python -m genkei.normalize.defillama --backfill`) dispatches blobs by `endpoint_name` prefix into `defillama.prices`, `defillama.protocol_tvl`, `defillama.stablecoins` — decoupled from collector per D-012, mirroring the existing daily collect/normalize split.
