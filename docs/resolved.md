### R-023 — DeFiLlama backfill mode + Phase 1 hygiene migrations (B-019)
- **Resolved:** 2026-05-10 (branch phase1-cleanup, commits `f6bb302` + `80cb37e`)
- **Outcome:** Closes the last high-priority Phase 1 item with full Option C scope (every backfillable DeFiLlama endpoint), plus the two D-010 hygiene additions baked in from the start. **Three new migrations:** (1) `defillama.protocol_tvl` — sibling to `defillama.protocols`, PK `(slug, chain, ts)`, FK to `protocols(slug)`, 30-day hypertable chunks; (2) compression policies on all four `defillama.*` hypertables (segmentby = most-filtered column per table, orderby `ts DESC`, compress chunks > 30 days old); (3) 90-day retention on `meta.raw_blobs` via a TimescaleDB `add_job` running a `meta.delete_old_raw_blobs` procedure daily inside Postgres. **Backfill collector** (`python -m genkei.ingest.defillama --backfill --since YYYY-MM-DD [--endpoint X]`) walks daily timestamps for prices, iterates known slugs for `/protocol/{slug}`, and known asset_ids for `/stablecoin/{id}`. Each fetch lands a `meta.raw_blobs` row with a backfill-shaped `endpoint_name` (`prices_historical_<date>`, `protocol_<slug>`, `stablecoin_<id>`). chain_tvl is intentionally not backfillable here — G-012, daily collector already pulls full chain history every run. **Resumability** per D-011: every prospective fetch checks `meta.raw_blobs.url` within a 14-day window; already-fetched URLs skip the HTTP call and copy the cached payload into the current run so the selected `source_run_id` still normalizes completely. Crashed-then-resumed runs do zero redundant work. **Backfill normalizer** (`python -m genkei.normalize.defillama --backfill`) dispatches blobs by `endpoint_name` prefix into `defillama.prices`, `defillama.protocol_tvl`, `defillama.stablecoins` — decoupled from collector per D-012, mirroring the existing daily collect/normalize split. ### ~~B-045 — Implement `genkei query` escape hatch~~
- **Resolved:** 2026-05-17 (branch genkei-query, commit `b30ce92`)
- **Outcome:** Closes out the Phase 3 CLI surface — now 7/7 real subcommands; only `news` (B-043) remains stubbed pending an actual GDELT data source. ROLLBACK`, Postgres rejects DML/DDL at the engine level. Shipped as a transaction mode rather than a dedicated DB role (functionally equivalent enforcement, no separate role to provision; a role-based variant is a small follow-up if/when we want belt-and-suspenders). (2) **statement_timeout** — `SET LOCAL statement_timeout = N` per query (default 30s, max 300s), inlined into the SQL string because `SET LOCAL` doesn't accept bind params (safe — value is range-validated int). (3) **row cap** — user's SQL wrapped in `SELECT * FROM (<user_sql>) AS q LIMIT N` so the cap is enforced server-side (default 100, max 100 000); capped results render a `(row cap)` marker in table mode. **Defense in depth:** the wrap also turns INSERT/UPDATE/DELETE into a parse-time SyntaxError (DML can't appear in a subquery), so the READ ONLY mode is a backstop rather than the only line of defense. **Multi-statement input** (`;` outside string literals) is rejected at parse time via a character-walk that respects quote state and Postgres's `''` escape convention — `WHERE col = 'a;b'` and `'O''Brien;was;here'` don't false-positive. Adds `--file` for SQL from disk, `--format table|json|csv` (plus `--json` shorthand matching other subcommands), and the same Decimal→string JSON convention the other subcommands use. Known Postgres errors (QueryCanceled, SyntaxError, ReadOnlySqlTransaction, UndefinedColumn/Table/Function, InsufficientPrivilege, GroupingError, DatatypeMismatch, InvalidTextRepresentation) render as one-line agent-readable `query error [Kind]: msg` lines on stderr, not stack traces — important for keeping the agent's debugging loop tight. **Live smoke:** `SELECT count(*) FROM sec.form4_transactions` returned 192,323; JSON top-issuer query returned CRM 52k, GOOG 25k; `--timeout-seconds 1` against `SELECT pg_sleep(3)` cancelled in <1s; INSERT cleanly rejected; `SELECT 1; SELECT 2` rejected at parse position 8; `--limit 5` against `generate_series(1,1000)` returned exactly 5 with the `(row cap)` marker. **Not shipped (deferred follow-ups):** dedicated read-only Postgres role (the transaction-mode guarantee is functionally equivalent); stdin pipe input (positional + `--file` cover the common shapes); EXPLAIN-wrap shortcut (users can write `EXPLAIN SELECT ...` themselves and it works fine).
